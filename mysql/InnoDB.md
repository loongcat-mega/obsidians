### 内存结构

#### Buffer Pool
缓存访问的表和索引数据，buffer pool被划分为多个页面，每个页面容纳多行数据，采用页面链表形式实现，采用lru算法缓存获取数据

##### LRU
当需要向buffer pool中添加新页面时，会逐出最近最少使用的页面，并将新页面添加到列表中间
![image.png](https://yaaame-1317851743.cos.ap-beijing.myqcloud.com/20250418110049.png)
- 头部是最近访问过的新页面
- 尾部是最近访问较少的旧页面

尾部是被逐出的候选对象

- 缓冲池的3/8 专用于旧子列表
- 列表中点是新旧列表交界处
- innodb将页面读入缓冲池时，首先将其插入到中点
- 命中缓冲池页面时，会使其变年轻，向头部移动
- 未被访问的页面会想列表尾部移动，从而老化

新旧列表都会随着页面更新变化

默认情况下，查询读取的页面会立即移到新的子列表中，对于mysqldump或者select没有where的子句的执行会将大量数据带入缓冲池，即使这些数据只访问了一次。这种情况会将经常使用的页面推送到旧列表中。

##### 缓冲池配置

- 越大越好，越大就越像内存数据库

##### 查看缓冲池信息
`show engine innodb status` 的 buffer pool and memory 部分


### Change Buffer
用于在二级索引页不在buffer pool时，缓存这些页面的更改，稍后会在其他读取操作将页面加载到buffer pool 进行合并，避免将二级索引页从磁盘读入缓冲池所需的大量随机访问IO

### 自适应哈希索引
使用索引键的前缀构建哈希索引，前缀可以是任意长度，并且可能只有B树中的部分值出现在哈希索引中，哈希索引为内存页面访问设计
![image.png](https://yaaame-1317851743.cos.ap-beijing.myqcloud.com/20250418112918.png)

Innodb存储引擎会监控对表上二级索引的查找，如果发现某二级索引被频繁访问，二级索引成为热数据，建立哈希索引可以带来速度的提升

只适合等值查询，范围查询不可用






### Log Buffer
日志缓冲区，保存要写入磁盘的日志文件数据
