### **1. 协议基础**​

- ​**传输层**​：早期设备多用 ​**UDP**​（端口54321），部分新设备可能改用 ​**TCP**。
- ​**加密方式**​：
    - 使用 ​**AES-128-CBC**​ 加密（密钥为设备Token的MD5哈希前16字节）。
    - 初始向量（IV）为 `0x17 * 16`（即连续16个`0x17`）。
- ​**Token**​：32字符的字符串（从设备固件或抓包获取），是通信密钥的基础。

---

### ​**2. 报文结构**​

每个miIO协议报文分为 ​**头部（Header）​**​ 和 ​**数据部分（Data）​**，总长度可变。

#### ​**2.1 报文头部（16字节）​**​

| 偏移量  | 长度（字节） | 说明                                         |
| ---- | ------ | ------------------------------------------ |
| 0x00 | 2      | ​**Magic Number**​：固定为 `0x2131`（表示miIO协议）。 |
| 0x02 | 2      | ​**报文长度**​：整个报文的长度（Header + Data）。         |
| 0x04 | 4      | ​**未知字段**​：通常为 `0x00000000`（保留或协议版本标识）。    |
| 0x08 | 4      | ​**时间戳**​：设备或客户端的Unix时间戳（秒）。               |
| 0x0C | 4      | ​**Token校验**​：设备Token的MD5哈希的前4字节（用于身份验证）。  |
|      |        |                                            |

#### ​**2.2 数据部分（加密前）​**​

- ​**明文数据**​：JSON格式的指令或响应（如 `{"id": 123, "method": "set_power", "params": ["on"]}`）。
- ​**加密后数据**​：通过AES加密后的二进制数据，长度需对齐16字节（PKCS#7填充）。

---

### ​**3. 通信流程示例**​

#### ​**3.1 设备发现（UDP广播）​**​

- 客户端发送 ​**明文**​ 广播报文（无加密）到 `255.255.255.255:54321`：
    
    json
    
    复制
    
    ```json
    {"cmd": "miIO.discover", "id": 123}
    ```
    
- 设备响应包含其IP、Token校验字段（Header中的4字节MD5）等。

#### ​**3.2 控制指令（加密通信）​**​

1. ​**构造JSON指令**​：
    
    json
    
    复制
    
    ```json
    {"id": 123, "method": "set_power", "params": ["on"]}
    ```
    
2. ​**加密数据**​：
    - 对JSON字符串进行AES加密（需填充至16字节倍数）。
3. ​**组装报文**​：
    - 头部字段填充（时间戳、Token校验等）。
    - 将加密数据附加到头部后。
